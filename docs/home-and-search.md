## Library workflow

Choose Search → Library → Add to Library, select a folder and allow automatic initial indexing to complete. Library manages the selected folder roots, document totals, Update Index, progress, Stop and removal from the local index. Only these explicitly selected roots are scanned; no whole-computer discovery is added. The index includes PDF and UTF-8 `.md`, `.markdown` and `.mdown` files; Update Index adds Markdown files in an existing library. Markdown files are limited to 8 MB and indexed as heading-based sections, with fenced-code headings ignored and block boundaries preserved. Section numbers are navigation anchors, not simulated PDF pages. Folder grants and index data persist locally. Update Index scans chosen folders again, skips successful unchanged files, retries failed documents, replaces changed documents transactionally and removes entries for deleted files only after a successful complete traversal. Stop cancels at bounded checkpoints, rolls back an interrupted document and retains completed documents; Update Index resumes by skipping those unchanged entries. An unavailable folder or failed traversal cannot trigger deletion cleanup. Removing a folder removes only its local indexed state, never its source files. Automatic file watching is not implemented.

The index lives in `~/Library/Application Support/Deerstalker/Search/library-v1.sqlite`. `LibraryIndex` owns the system SQLite connection in an actor and uses FTS5 `unicode61` with positional data, diacritic removal and BM25 candidate ranking followed by a bounded proximity preference of at most 25% for query groups occurring near each other within a candidate. The candidate set is the first 200 FTS hits, so this is not a globally exhaustive proximity reranker. The first three extracted lines form a modest heading boost; they do not establish true typographic heading detection. The index records extracted PDF page text, parsed Markdown text, file revisions and extraction failures. A revision prefix invalidates earlier successful extraction records during the next manual Update Index. It does not retain PDF objects for idle searching. One PDF is extracted at a time; reading/indexing very large individual documents can delay other requests to that actor. SQLite page storage is persistent rather than retaining all library text in a Swift array.

All entered words are required. Quotation marks retain an exact phrase, subject to FTS tokenisation; SQL and FTS operators in ordinary input are escaped. Queries are limited to 24 groups and 512 characters. Search opens a separate window from Home or Command-Shift-F. Documents are ordered by their best result; expanded child rows follow page/section order. The left pane shows an asynchronously generated first-page PDF cover or an authored native Markdown cover, the document name and short location rows. Long snippets stay in hover context and bounded assistant evidence rather than filling the sidebar. Selecting a location navigates the right-hand original preview; Previous/Next follows visible grouped order. A document-name/path filter narrows that navigation. Scores are not presented as probabilities. Query changes debounce for 250 ms and discard stale responses.

The PDF preview loads away from the main actor and discards cancelled or superseded loads. Moving between results in the same file reuses the document; index refresh invalidates it. Search highlights use non-interactive PDF page overlays with PDFKit geometry conversion, supporting text selection without changing annotations or source bytes. The word matcher handles case/diacritic folding and phrases across token separators, and avoids partial-word highlights. It approximates SQLite tokenisation rather than guaranteeing identical handling of every Unicode script. The cover cache is bounded at 64 small PNGs and retains no PDF objects. Large individual PDF extraction or thumbnail decoding is not pre-emptible inside the native call.

Markdown previews reuse the independently authored escaped HTML/MathML renderer with stable section anchors, light/dark colours and highlighted visible text. Tables, local images and supported mathematics render locally. Authored scripts and network loading remain blocked; fixed native DOM code applies highlights and scrolls to the selected section. Unsupported renderer content can still be indexed as text and shows a short Open prompt when preview generation fails. Explicit Open opens the Markdown document in its reader; retaining the selected section in that separate editor is not implemented. PDF Open retains its page-navigation request. The left pane exposes folder selection, index progress and Stop.

## Optional Apple Intelligence answers

Ask toggles a right-hand panel with a short transition that respects Reduce Motion. It uses only the on-device `SystemLanguageModel.default` through Apple Foundation Models; there is no provider selector, PCC path, cloud fallback or entitlement handling in the application. A request uses up to six supplied passages, totalling at most 2,600 UTF-8 bytes; the question is bounded to 500 bytes. Settings → Ask → Response detail offers Low, Mid and High, defaulting to Mid, with output limits of 350, 800 and 1,400 tokens respectively. Each request snapshots the selected detail; existing replies remain unchanged. Low requests a short direct answer, Mid a few explanatory paragraphs and High a fuller structured explanation. These are depth preferences and ceilings, not guaranteed word counts or separate reasoning models. The user explicitly starts each request. No model weights or runtime are bundled or downloaded by Deerstalker. Availability is checked at runtime: macOS 26+, eligible hardware, Apple Intelligence enabled and its system model ready. Normal lexical search remains independent. See [Apple's Foundation Models documentation](https://developer.apple.com/documentation/foundationmodels/generating-content-and-performing-tasks-with-foundation-models).

`Assistant/AssistantPassage.swift`, `DocumentAssistant.swift`, `AssistantPanel.swift` and `AppleIntelligence.swift` form the reusable Ask boundary used by Search and the PDF reader. Callers supply generic passages or an asynchronous retrieval closure, a topic and source navigation. The module has no dependency on LibraryHit, HomeModel, SQLite or PDFKit; SearchAssistantContext adapts library hits, while PDFAssistantContext handles reader-specific extraction. Sent questions appear on the right in brick bubbles, replies on the left in adaptive neutral bubbles. Each reply retains its own initially collapsed source disclosure; expanding it reveals numbered document/location buttons and short excerpts. Subsequent turns cannot renumber earlier sources. Answer bubbles render inline Markdown emphasis while preserving paragraph breaks. New conversation clears the local transcript and draft. The conversation remains in memory only, and closing/reopening the panel preserves completed messages for that document while stopping pending work.

The PDF reader toolbar now exposes Ask. Each request copies the current document bytes, including committed unsaved note changes, into an actor-owned PDFKit document. It reads page text on demand, ranks pages using question terms, modest prefix/one-edit matching and a current-page preference, and retains up to six bounded passage candidates. An explicit owned selection takes precedence. Paragraph-window selection keeps relevant later text rather than always clipping a page's opening. This is lightweight lexical passage retrieval, not whole-document reasoning, OCR, an embedding index or a guarantee of semantic recall. Reading shows progress and supports Stop; a single PDFKit extraction call is not itself interruptible. PDFs above 256 MB are refused; extracted text considered per page is capped at 100,000 characters. Locked or copy-restricted documents are refused; an explicitly unlocked copyable PDF can use the successful unlock credential in reader memory, cleared on document replacement and released with the session. Image-only pages require future OCR. No page-text cache or background model prewarming remains idle between requests.

Evidence is limited to 2,600 UTF-8 bytes, each question to 500 bytes, and the last two turns supplied as conversational context to 900 bytes. Old citation numbers are removed from history, which is explicitly excluded as evidence. The on-device model receives a fresh bounded prompt for each turn. Document passages are untrusted data. Replies prioritise their supplied passages and cite PDF claims; cautious outside knowledge must be labelled General context and must not be attributed to the PDF. A wholly uncited reply is accepted only with that explicit qualification. Individual, comma-separated and bounded numeric-range citations resolve against that reply's supplied evidence; malformed, overflowing and unknown source numbers are rejected. This checks source identities, not factual entailment, and cannot guarantee model compliance, truth or complete-document coverage. The user can expand Sources and follow an individual source to its PDF page or Markdown section. The citation carries the actual bounded excerpt supplied to inference, rather than a quotation invented by the model. A Unicode/whitespace-tolerant contiguous token match maps the excerpt to native page ranges or section-scoped DOM marks; mathematical operators are preserved. Limited clipped-word tolerance requires a substantial contiguous phrase. A fresh click identity refocuses the same source after manual scrolling. A PDF whose excerpt no longer matches is opened at the referenced page with a short warning and no substitute keyword highlight. Reader and Search use non-interactive yellow page overlays so marks remain visible without selection focus; Markdown marks stay scoped to the cited heading section. These focus marks are transient, do not create PDF annotations, and do not dirty or save the source. They do not establish sentence-level factual entailment. Stop, closing the panel, document/file/content changes and search/index/filter changes invalidate pending responses. Document changes also clear the transcript and draft. Ordinary page navigation preserves the conversation. The Foundation Models context window is finite; byte bounds reduce prompt size but are not an exact token-count guarantee. See [Apple's context-window guidance](https://developer.apple.com/documentation/foundationmodels/managing-the-context-window).

## Spelling and related concepts

Ordinary keyword search remains fast and literal. When it returns no hits, the app offers Did you mean suggestions drawn from the current FTS5 vocabulary. Adjacent transpositions and one/two-character edits are compared conservatively; quoted phrases and very short terms are not rewritten. Suggestions must themselves retrieve an actual indexed result, and applying one is an explicit click. Vocabulary candidates are capped at 4,000 per unknown word and at most two unknown words/six query groups are considered, so this is a bounded spelling aid rather than exhaustive correction for every language.

Explore explicitly invokes the on-device system model to translate a question or indirect expression into up to four short English search queries, using at most 160 indexed vocabulary hints. The model’s JSON plan is validated and searched through the local index. If generated qualifiers prevent matching, the app retries with only the plan’s actual indexed content words, or with grounded content words from the original request. Only real retrieved locations enter the results. Reciprocal-rank fusion combines query result lists without comparing unrelated BM25 magnitudes; each result retains the query that actually matched for its preview highlights. The screen labels these Related results, preserves the original input and offers Keywords to return to literal search. Progress and Stop remain visible during generation; stale or cancelled plans cannot replace the current query’s results.

No model runs over every page during indexing and no embedding model, vector store or generated semantic-tag index is added. This is model-assisted query expansion over a persistent lexical index. It can improve discovery for some indirect wording and synonyms, but does not promise arbitrary metaphor understanding, exhaustive semantic recall or calibrated relevance. Optional dense retrieval remains a separately evaluated future direction. [SQLite’s FTS5 vocabulary module](https://www.sqlite.org/fts5.html#the_fts5vocab_virtual_table_module) supplies the local term vocabulary.

## Saved PDF highlights

The Search PDF toolbar now offers Highlight, a fixed colour menu and Undo last highlight. Select text in the PDF and choose Highlight to save standard PDF Highlight annotations immediately to the source file. Each selected line gets [annotation-relative quadrilateral points](https://developer.apple.com/documentation/pdfkit/pdfannotation/quadrilateralpoints) and 30% opacity. The eight choices are Yellow `#F0E442`, Orange `#E69F00`, Sky blue `#56B4E9`, Bluish green `#009E73`, Blue `#0072B2`, Vermilion `#D55E00`, Reddish purple `#CC79A7` and Black `#000000`; names accompany the colour swatches and no arbitrary picker is exposed. The values follow [Okabe and Ito's CUD palette](https://jfly.uni-koeln.de/color/). Transient search overlays also use the palette yellow, while saved annotations remain separate.

PDFHighlightStore builds changes in an isolated PDF instance and reuses PDFCommentGraph/PDFReplyWriter for annotation relationship serialisation. It verifies a SHA-256 source snapshot before preparation and again inside a coordinated atomic write. A PDF already open in the application's document reader is refused to avoid competing ownership. Encrypted, form/permission-protected and unsupported structures are refused; at most 200 selected lines and a 256 MB input are accepted. Save failures leave the preview and source unchanged. One previous byte snapshot supports Undo while the same preview remains open, restoring the exact pre-highlight bytes after a fresh revision check; this is not a multilevel or cross-session history. Saving displays a spinner. Basic text, page count, palette values, markup quadrilaterals, file permissions, external-change rejection and undo are covered by fixtures. Existing reader comments/replies reuse the established preservation writer, but broad document fidelity and signature/rotation edge cases remain limited. Markdown currently has transient search marks; saved Markdown markup is outside this feature.

## Convert workflow and limits

Convert opens a dedicated workspace. Add or drop files, choose Convert, review individual PDFs one page at a time and choose Save PDFs to select an output folder. Inputs do not need matching extensions. Each source file produces a separate PDF; duplicate basenames receive numbered output names. Already saved items are skipped on retry. Combining remains an explicit separate tool. Conversion runs in an actor, reports individual failures and checks cancellation between files and pages; closing the workspace cancels preparation and discards its temporary results. Native Word import itself is not interruptible. Saving disables closing while copies complete.

Images are validated with ImageIO content decoding rather than filename extensions; PNG/JPEG and multi-frame TIFF fixtures pass. Each decoded frame becomes a Letter-sized page, fitted within margins with orientation correction and a white background; thumbnail decoding caps the longest edge at 6,000 pixels. This is a bounded document conversion, not a promise of original-resolution image archiving. The current limit is 1,000 frames per source.

Word uses native attributed-text import and a private TextKit layout stack rather than the former Core Text text-only paginator. Supported DOCX preserves imported text styling/colours, inline raster images, ordinary tables, explicit page breaks and the document's single-section paper size/margins. Text stays searchable; imported HTTP/HTTPS/mailto links become PDF link annotations. Images are fitted within the printable area. The system importer silently omitted the independent fixture's ordinary DrawingML image, so Deerstalker now reads the OOXML package, substitutes temporary text markers before import and restores decoded attachments afterwards. Package data stays in memory and never becomes extracted filesystem paths. No third-party Word engine or vendored library is required.

The bounded package reader accepts stored/deflated ZIP entries, verifies CRCs for consumed parts and rejects duplicates, encryption, ZIP64 and excessive sizes. Limits are 64 MB input, 1,024 entries, 30 MB per expanded entry, 100 MB total expanded size, 20 MB XML, 200 images and 40 million decoded image pixels. XML external entities/DTDs are disabled or rejected. Embedded images are decoded with ImageIO at a maximum 4,800-pixel edge; missing, externally linked or undecodable images fail explicitly.

The supported DOCX profile still rejects unrecognised equation structures, charts without a usable inline preview, floating/cropped/transformed drawings, text boxes, unsupported fields, footnotes/endnotes, tracked changes, content controls, multiple sections and multi-column layout instead of silently claiming full preservation. Supported mathematics, single-section headers/footers and inline object previews are described below. Ordinary table pagination passes the multi-page fixture, but repeated headers, merged/nested cells, custom numbering and arbitrary Office typography still require broader tests. This is not the Microsoft Word page-layout engine; the short layout warning remains. Legacy `.doc` still relies on native import and has narrower evidence from a native-generated text fixture.

Markdown conversion now generates self-contained escaped HTML for headings, paragraphs, emphasis, lists, code, column-aligned tables, local images and formulas. Local images are decoded and embedded as PNG data; resources outside the document folder, missing images and remote image URLs fail explicitly. Images are capped at 4,800 pixels on their longest edge, 30 MB per source and 60 MB total decoded PNG data. HTML source is limited to 8 MB. Links do not initiate network requests. Authored scripts, network access and external frames/fonts are blocked by CSP; only a fixed native DOM measurement script runs.

A first-party TeX-notation parser emits native MathML for common fractions, roots, scripts, Greek symbols, operators, sums/integrals, accents, font variants and matrix/aligned/cases environments. It does not implement arbitrary TeX macros, packages or the complete LaTeX language; unknown commands and malformed notation produce concise per-file errors. Formula length, nesting and matrix-environment limits prevent unbounded recursive parsing. No KaTeX/MathJax source is copied, downloaded or required. System WebKit renders the resulting MathML using local fonts.

PDF output measures text lines, table rows, images and formulas before choosing page cuts, then captures WebKit PDF regions and composes them as vector content on Letter pages through CoreGraphics. This avoids cutting ordinary lines or fitting-size figures across page boundaries. The current limit is 1,000 pages and a 40-second rendering deadline. Over-height blocks, full Markdown/CommonMark conformance, repeated headers on long tables, advanced nested lists and comprehensive TeX compatibility still need broader fixtures. Reader preview remains the older native block renderer; these richer features currently apply to Convert.

## Word mathematics, page furniture and inline artwork

Office Math is read from OMML rather than recognised with OCR. First-party conversion maps runs, fractions, roots, sub/superscripts, prescripts, delimiters, n-ary operators, functions, limits, accents, bars, matrices and equation arrays to native MathML. Unknown structures fail explicitly. System WebKit renders generated MathML into tightly bounded PDF artwork attachments; this does not provide an editable Word equation or promise exact Office font/spacing fidelity. Font styling support is partial. Inline and display equation containers are handled, including a display equation directly in the body. There is no external API, CDN, scripting from document content or model download.

Single-section headers and footers load their own package parts and relationships, including their inline images/equations. Default, first-page and even-page variants honour `titlePg` and `evenAndOddHeaders`; missing first/even parts remain blank when those variants are enabled. Decimal page-number starts are supported. Simple and standard complex `PAGE`/`NUMPAGES` fields are resolved after the body page count is known; other dynamic fields and number formats fail explicitly. The body is laid out before page drawing, then furniture is drawn within the document's header/footer distances. Oversized furniture fails rather than covering the body. Multiple sections and their inheritance rules remain unsupported.

Inline DrawingML rectangles, rounded rectangles, ellipses, triangles, diamonds, lines and static numeric freeform move/line/quadratic/cubic/close paths can be rendered locally when explicit colours and supported properties are available. The generated SVG is rendered through the same bounded WebKit PDF-artwork path. Inline embedded objects with a decodable local VML raster preview use that existing preview; the embedded object itself is not executed or interpreted. No raster preview is invented for an unsupported object. Theme/effect-heavy shapes, SmartArt, arbitrary charts, floating placement, text boxes, rotations, clipping and unsupported paths still fail explicitly. This is a bounded renderer, not a general Office drawing engine.

Word artwork uses a non-persistent WebKit store, restrictive CSP and a fixed native measurement script. Capture dimensions are bounded below 1,900 CSS pixels with a 25-second per-artwork deadline and cancellation. Preparation remains indeterminate with the active-file spinner during import/artwork rendering; body layout and page drawing report measured progress afterwards. The expanded 59 checks cover the earlier Word cases plus real fraction/root/power output, structural matrix/n-ary/accent mappings, first/even/default headers, actual page/total fields, missing and oversized furniture, unknown mathematics, visibly coloured shapes, local embedded-object raster previews, freeform conversion and artwork cancellation. Poppler-rendered pages confirm the formula, furniture, shape, preview and freeform output. No native app build/install or live dialog review has been performed.

Header selection follows the documented single-section rules in [Microsoft's header reference](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-replace-the-header-in-a-word-processing-document); fraction structure follows the [Office Math fraction definition](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.math.fraction). These sources describe the file format, not a claim of full Word compatibility.
