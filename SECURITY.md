# Security

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on the repository's Security tab when available. If that option is unavailable, open an issue asking for a private reporting channel without including exploit details, private documents or credentials. Do not post account tokens, SSH passwords, Keychain exports or document contents publicly.

Include the app version, macOS version, affected operation, expected and observed behaviour, and a minimal synthetic reproduction. Describe any document-loss or account-access impact. There is no guaranteed response time or paid support commitment.

## Scope

Reports about credential handling, imported files, process execution, document integrity and connected-service boundaries are welcome. Use only accounts and devices you are authorised to test. Do not probe third-party services through remile. Provider security issues belong in the provider's reporting process.

Report against the latest stable release where possible. Older releases may retain different integrations or assets. Source fixes do not retroactively update installed apps or older release packages.
